# PaperBridge 0.4.0 发布验收

## 发布范围

- 批次内跨论文、跨分段复用解析引擎与模型；失败、超时或达到回收阈值后重新启动。
- 公式识别增加可选 CUDA 后端；桌面端默认自动选择，初始化或推理失败时回退 CPU 并记录原因。
- Windows 发行物拆为可独立运行的基础客户端和可选 GPU 加速补充包，本地完整目录包含两者。

## 性能与质量证据

固定三篇论文共 9 页，按 CPU、CUDA、CUDA、CPU 交错执行。CPU 端到端中位耗时 132.761 秒，CUDA 为 58.985 秒，下降 55.57%；公式阶段约下降 75%。四轮原始内容和资产哈希一致，CUDA profile 中公式模型使用 CUDA provider，同时保留少量 CPU shape 运算。

该数字只代表 RTX 4070 Laptop、当前驱动和这组三篇样本。它证明此处存在可复现加速且测试输出字节一致，不代表其他论文、GPU 或所有识别内容都能获得相同比例，也不能替代公式语义人工核对。详见 [GPU公式识别可行性与性能验证](GPU公式识别可行性与性能验证.md) 和 [模型复用实现与验收](模型复用实现与验收.md)。

## 自动化与发行检查

- 源码测试：68 项通过。
- 生产路径 GPU 回归：三篇共 9 页、6 个新分段均报告 `actual=cuda`，provider 顺序为 CUDA、CPU；没有命中旧缓存，素材完整性全部通过。
- 生产路径与先前 CUDA 对照轮次逐文件比较：可审计内容与资产 `changed_files=0`。
- 冻结版 CPU 回归：隔离开发环境变量、仅用包内模型完成 13 份文档；检查点复用、损坏和加密 PDF、停止后续跑、超时清理及旧修订导出全部通过。
- 冻结版 GPU 回归：DiTTo 19～21 页两个新分段均报告 `actual=cuda`，provider 顺序为 CUDA、CPU，11 张图片素材检查通过；既有 `unbalanced_display_math` 仍标为需复核。
- 原生窗口：实际 `PaperBridge.exe` 成功打开并自动关闭，退出码 0，启动环境不含开发 Python 路径。
- 基础 ZIP 与 GPU 补充 ZIP 均通过逐条解压测试；基础包不含 GPU DLL，补充包覆盖构建清单中的全部 GPU DLL。最终大小与 SHA-256 见发行资产旁的 `.sha256` 文件。

以上是机械完整性和运行路径验收，不代表识别准确率为 100%，也不等同于全新 Windows 机器验收。
