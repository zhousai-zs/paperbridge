# 论文 PDF 转 Markdown：选型记录

调研日期：2026-10-20；本机验证日期：2026-10-21。

目标是保留论文阅读顺序、图像、公式和表格，并产出可直接交给 agent 的文件夹。输出成功、机械完整性、语义正确性是不同指标。

| 工具 | 适配能力 | 本项目决策 |
| --- | --- | --- |
| [MinerU](https://opendatalab.github.io/MinerU/zh/usage/tiers/) | 单多栏、OCR、公式识别、表格与结构化输出；4.x 支持 ONNX CPU 和本地 VLM | 核心引擎，实际固定测试 4.0.12。Basic 用于快速转换；Standard 用于复杂内容 |
| [Docling](https://github.com/docling-project/docling) | 文档结构、多种输入输出、OCR 与表格，具有公式增强能力 | 作为备选；本次没有安装或做本机性能对比，不声称效果更差 |
| [Marker](https://github.com/datalab-to/marker) | Markdown、图片、公式、表格；本地模型与可选 LLM 增强 | 作为备选；本次未实测，部署与模型资源需另核对 |
| [PyMuPDF4LLM](https://github.com/pymupdf/PyMuPDF4LLM) | 轻量文本抽取、阅读顺序、图片和表格 | 不作为唯一引擎；[维护者明确说明](https://github.com/pymupdf/pymupdf4llm/discussions/390)公式抽取尚有限制，可能只能输出图片 |

## 实现取舍

没有重新训练 OCR 或自造版面算法。PaperBridge 在解析引擎外增加批处理、中文路径处理、内容哈希命名、输入快照、断点复用、失败报告、页面覆盖检查、图片引用检查、每页原图、公式/表格裁图、结构 JSON 和 agent 阅读说明。

每次转换只使用本机解析。模型安装需要联网，正式验证使用 local 模型源。没有接入付费云服务或上传论文。源文件不会被覆盖。输出 Markdown 与素材必须整体搬运。

[MinerU SDK](https://opendatalab.github.io/MinerU/zh/usage/sdk_api/)用于解析；[保存协议](https://opendatalab.github.io/MinerU/zh/reference/output_files/)用于生成 Markdown、结构和图片。固定小版本防止上游协议变化导致静默损坏。

## 验证数据

- [Attention Is All You Need](https://arxiv.org/pdf/1706.03762)，15 页，英文单栏、数学表达式、矢量图和表格。
- [In Search of an Understandable Consensus Algorithm](https://raft.github.io/raft.pdf)，18 页，英文双栏、图示、表格、算法和参考文献。
- [OmniDocBench](https://github.com/opendatalab/OmniDocBench)中固定选择的 7 页学术文献及人工标注，包含中文单栏、中文双栏正文加跨栏表格、中英混合表格、英文单双栏公式和复杂图。将原始图像无损嵌入 PDF，明确作为扫描版测试。
- 4 份自建回归样本，覆盖中/英文 × 单/双栏，包含指定顺序标记、矢量图、表格和简单公式。

原始公开论文及基准数据保留各自版权；本地样本仅供验证。源码可单独打包，不需要附带论文或模型。测试集是小规模功能验证，不等于在完整 OmniDocBench 上的排名或对所有论文模板的保证。
