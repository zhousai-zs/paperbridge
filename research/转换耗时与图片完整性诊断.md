## 耗时结论

原报告累计转换用时 **3025.26 秒（50.42 分钟）**。引擎日志累计推理用时 **2648.45 秒（44.14 分钟，87.54%）**。其余约 6.28 分钟包含进程/模型初始化、图片导出、组装、原页生成等；旧报告不能把这部分精确拆开。

下表的公式识别时间来自引擎进度条整数秒，属于近似值；总耗时来自各篇原始 report.json。

| 论文 | 总耗时（秒） | 引擎推理（秒） | 公式识别约（秒） |
| --- | ---: | ---: | ---: |
| DiTTo.pdf | 605.97 | 583.36 | 476 |
| FAPE-IR.pdf | 308.05 | 283.25 | 151 |
| IRPO.pdf | 224.70 | 199.30 | 103 |
| MMFE-IR.pdf | 172.23 | 147.51 | 65 |
| JarvisIR.pdf | 161.73 | 132.69 | 57 |
| HarnessIR.pdf | 153.74 | 127.05 | 12 |

DiTTo 的两个分段累计公式识别约 **476 秒（7.93 分钟）**，约占其 605.97 秒总耗时的 78.55%。24 篇累计公式识别约 1237 秒，是最主要的可辨识耗时项。

当前源码环境的 ONNX Runtime 提供 CPU/Azure provider；MinerU 安装源码的公式后端明确固定为 CPU（`PPFormulaNetPlusMONNX` / `ort_session`）。这条公式识别路径不是仅安装 GPU 运行库就能切换的。每个分段使用独立引擎进程，也会反复初始化模型；以隔离、超时和停止可靠性换取额外开销。

本次没有降低 Standard 质量或关闭公式识别，也没有声称已经提升推理速度。后续性能优化应先基于新增计时比较公式后端和线程配置；跨篇常驻模型需要另行设计取消、崩溃恢复与内存回收。

## 已实施的防护

- 检查图片引用是否真实存在且能解码，覆盖 Markdown、内嵌 HTML 和 JSON 中的图片路径。
- 检查点生成和复用都执行上述检查，弥补“图片从未写入，却不在文件哈希清单中”的漏洞。分段必须覆盖预期页码。
- 每段默认首次尝试加一次自动重试，适用于解析错误、超时和校验失败；可通过 `--retries 0-5` 控制额外次数。失败仍会继续处理本批其余论文。
- 已完成分段复用；失败/无效分段的旧文件及日志移入该结果的 `history/`，重试在干净分段目录执行，避免残留图混入。用户停止不自动重试。
- 最终校验不通过的素材问题标为失败，保存 `integrity.json`；纯内容问题仍标为需复核。损坏原页图在重跑时重新生成。
- `report.json` 新增各阶段计时、每段各次尝试耗时、引擎导入/解析/保存/校验耗时，以及从日志提取的推理和公式等阶段耗时。
- 窗口显示具体识别阶段、阶段内数量、已用秒数、重试和最终校验。
- 新增只读 `verify` 命令，可单独检查旧结果而无需运行推理。
- 修复单引号 HTML 图片路径及结构中 `img_path` 的重定位。

## 验证与使用

44 项程序测试通过，真实转换与打包版验收摘要见配套 [conversion-validation.json](conversion-validation.json)。批量校验详情、原始日志和截图留存于本地，未上传。测试中的故障注入覆盖图片从未保存、图片损坏、解析进程失败、超时、重试耗尽、禁用重试、有效分段复用、原页恢复与用户停止。

检查原有结果：

```powershell
.\.venv\Scripts\python.exe -m paperbridge.cli verify "D:\结果" --report "复查结果.json"
```

沿用原文件、输出目录、页码、模式和分段参数重跑即可复用完整检查点。更换这些转换参数会生成新的结果目录；修改重试次数不会改变目录。

机械完整性通过表示保存下来的结构和引用一致，不表示所有原始图都被检测到，也不表示文字、公式和阅读顺序都准确。
