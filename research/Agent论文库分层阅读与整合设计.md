# Agent 论文库：分层阅读与整合设计

日期：2026-10-22。适用库：`D:\KnowledgeBase\papers\图像复原`。

状态：设计稿。本文基于现有库的只读检查编写；尚未生成全库理解摘要、检索索引或自动维护程序，也未修改现有知识库。

## 1. 核心决策

把“每次重新理解全文”改成“首次建立有依据的理解记录，之后按问题检索、回读和更新”。

保留一篇论文一个文件夹、一份知识地图管理分类与关系。新增四层阅读资料：

**全库短索引 → 单篇理解摘要 → 相关章节与证据块 → PDF 原页。**

另将有复用价值的跨论文分析保存为专题笔记，但专题笔记也必须能追溯到原文。

短索引回答“该找谁”，理解摘要回答“它做了什么、适用什么条件”，原文回答“依据是什么”，跨论文分析回答“这些结果放在一起意味着什么”。不能用同一种短摘要承担所有任务。

## 2. 当前库的实际约束

本次扫描得到 25 篇、495 个正文页标记，`document.md` 合计 2,070,941 个字符；现有知识地图约 23,096 个字符。字符数不是模型 token 数，也不是已完成的内容质量评估。

现有资料已经提供不少可复用的基础：

- `document.md`：正文、公式、图片链接、HTML 表格和 `source_page` 页标记。
- `document.json`：页、块类型、块序号、坐标等结构。
- `source.pdf`、`pages/`、`evidence/`：核对原始证据。
- `知识地图.md`：全库分类、资料入口、论文关系及依据。

这些足以支持第一版，不必先增加翻译或搭建独立向量数据库服务。

但结构不能直接当语义：例如 DPMambaIR 的 `III. METHOD`、`A. Problem Definition` 和 `B. DPMambaIR` 在识别稿里都是二级标题。章节索引必须检查编号及上下文，不能只按 `##` 切割并假定同级。

现有维护记录还指出 DiTTo 有公式标记不配对问题、各篇均未完成整篇识别准确性认证。新索引须继承这些限制，不能把“检索到了”变成“识别正确”。

## 3. 四层分别保存什么

以下长度均为初始设计目标，后续按真实查询调整，不是已经测得的最优值。

| 层级 | 内容与粒度 | 何时读取 | 维护方式 |
| --- | --- | --- | --- |
| 全库短索引 | 每篇约 100–200 个中文字等量内容，另加标题、英文关键词、路径、版本、覆盖状态 | 每次开始；当前 25 篇可以整体浏览 | 从地图、理解摘要和文件清单派生 |
| 单篇理解摘要 | 每篇约 800–1,500 中文字；核心机制、条件、证据入口、未知项 | 读取初筛相关的几篇 | AI 阅读原文后形成，随源文件更新 |
| 章节与证据块 | 原文的章节、段落组、表格、公式组、图及图注 | 要分析机制、数据、差异或验证结论时 | 程序提取位置，AI 按需判断含义 |
| 原页 | PDF 物理页、原页图片和已有裁片 | 关键数值、公式、图结构、解析可疑处 | 保持原始资料，记录具体核对范围 |

短索引不能堆成长摘要；理解摘要也不能变成每次必读的 25 份全文替身。

### 3.1 全库短索引

每条至少包括：

- 稳定论文 ID、正式标题、简称、目录和版本标识。
- 一句话：研究问题、采用路线、主要适用场景。
- 从知识地图导出的领域、任务、方法标签；保留重要英文术语和缩写。
- 理解摘要、章节索引、原文与 PDF 的入口。
- 已阅读范围、尚未覆盖内容、源文档是否变化。

例如检索“规划与记忆”时，除了中文标签，还应展开 `planning`、`memory`、`trajectory`、`tool selection` 等候选词。词义需按问题收窄；例如 memory 可能是推理记忆，也可能是显存。

短索引是一份机器可读的派生目录，不成为第二份分类权威。手动分类仍在知识地图维护。

### 3.2 单篇理解摘要：重点是可检索的理解，而非缩写摘要

建议统一使用以下内容结构，但允许某些字段明确写“未覆盖”或“不适用”：

| 字段 | 要回答的问题 |
| --- | --- |
| 问题和边界 | 输入、输出、目标退化、已知条件是什么？ |
| 核心机制 | 信息如何流动？关键模块分别做什么？训练和推理有何区别？ |
| 与已有工作的差别 | 作者声称的新意是什么？哪些差别已能从正文确认？ |
| 实验条件 | 数据集、退化生成、训练／测试协议、指标、工具池与计算条件是什么？ |
| 主要证据 | 哪些实验或消融支撑哪些论断？结果适用于什么条件？ |
| 局限与失败 | 作者报告了什么？AI 推断了什么？哪些暂时不知道？ |
| 阅读入口 | 方法、关键公式、主要结果、消融、局限分别在哪些章节和页？ |
| 阅读覆盖 | 已读章节、未读附录、核对过的表／图、待确认事项 |

每项重要断言绑定证据位置。区分“作者声称”“实验报告”“AI 分析”；分析性推断需要写出前提。

只读摘要时，只能形成明确标注覆盖范围的初筛记录，不能填成“方法和实验已理解”。“原文未提及”“已检查指定章节但未找到”和“尚未阅读”也必须分开。

第一遍可先覆盖摘要、方法主干、实验设置、主要结果和结论；附录、证明和细节按问题补读。若目标是完整精读，就必须另行安排全篇覆盖，不能靠压缩格式省掉这项工作。

### 3.3 章节和证据索引

第一版采用“章节父块 + 可返回的子块”。搜索命中一个段落时，同时返回所属章节、前后文入口以及相关图表入口。

切分规则：

1. 优先沿真实章节和语义段落划分。页码用于定位，不把换页自动当成语义边界。
2. 长章节再分段落组；保留章节路径和必要的前后文。初始以约 600–1,200 tokens 为普通文本子块目标，使用实际 tokenizer 后再测。
3. 完整公式、变量定义、图与图注、表头与表体尽量作为关联单元。跨页表格需要明确连接；超大表格按行分片时重复表头并保留整表入口。
4. 参考文献作为独立区域。检索到某篇名字出现在参考文献中，不构成采用其方法的证据。
5. 从 MD 得到的文本位置与 JSON 块不一定一一对应。只有确认匹配的记录才填 JSON 块序号／坐标；无法对齐就保留 MD 和原页定位。

建议记录字段：

```text
paper_id, source_revision, chunk_id, section_path, content_type
pdf_page_start, pdf_page_end, md_line_start, md_line_end
text_hash, text_or_local_pointer, related_chunk_ids, page_image_paths
json_block_refs（可空）, alignment_status, parse_warnings
```

证据 ID 在同一源版本内稳定；版本变化时重新解析和匹配，不承诺旧行号或块号永久有效。对外引用优先展示“论文 + 章节／表号 + PDF 物理页 + 可打开入口”，行号用于程序定位。

**本库实际例子：**当前 DPMambaIR 识别稿中，方法入口为第 107 行、PDF 第 3 页；退化感知状态空间模块入口为第 191 行、第 5 页；实验设置入口为第 303 行、第 7 页；失败边界分析入口为第 499 行、第 10 页。这些是本次读取确认的位置，不代表相关内容已经完成语义核验。询问核心模块时可直接读取相应小节及变量定义，无须先装载整篇。

## 4. Agent 每次怎样工作

### 4.1 通常的问答与方法比较

1. **界定问题。**区分找论文、解释方法、比较实验、全库综述、提出研究假设。提取比较维度和所需证据类型。
2. **浏览短索引。**对当前全库作一次低成本筛选，同时检查索引是否过期。初选约 3–6 篇只是起点，不是固定上限。
3. **读取相关理解摘要。**据研究对象、方法机制和实验条件收窄；缺摘要则直接补读相关原文，不把无摘要论文排除。
4. **搜索原文。**在候选论文内查关键章节，并进行一次全库关键词／别名补查，防止短索引漏掉相关论文。地图关系用于扩展候选，不能替代原文证据。
5. **读取命中上下文。**核对定义、条件和反例；关键图表或解析警告触发原页查看。
6. **建立证据对照。**按同一组问题比较各篇，分清已支持、部分支持和未知。
7. **形成回答。**重要事实有原文出处；跨论文推论写出依据和条件；说明实际覆盖了哪些论文。
8. **按需回写。**补充新确认的摘要字段，保存值得复用的专题分析，并更新依赖版本。

“没有搜到”只表示当前检索无结果。需要改写术语、扩大候选或检查相关章节后，才能说明检索边界；通常不能据此证明全文不存在该内容。

### 4.2 全库综述必须走另一种流程

对于“这 25 篇有哪些路线”“哪些文章都采用了某机制”这类要求完整覆盖的问题，不能只返回相似度最高的几篇。

- 首轮覆盖全部 25 条索引和各篇相关字段。
- 对字段未知、可能相关或结论存在冲突的论文逐篇补查。
- 分批阅读，例如每批 4–6 篇，把结果写入同一张带证据的覆盖表。
- 最后归并类别，检查遗漏、重复版本和反例。
- 输出明确范围，例如“已检查 25 篇，其中 3 篇相关机制仍待核对”。未完成覆盖时不能使用穷尽性措辞。

因此节省的是反复阅读无关全文的成本，不是承诺任何问题都只读三篇就能解决。

### 4.3 上下文预算与停止条件

初始可尝试将普通比较问题的资料输入预算设为约 15,000–25,000 tokens，分配给短索引、选中摘要和原文证据，并为推理与输出另留空间。实际预算需随模型窗口、题目和数据调整；首次建立索引的成本单独计量。

当各比较维度已有原文依据、关键条件已确认、相关反例已检查时，可停止补读。证据不足则继续分批读取，或明确保留未知；预算用尽不等于问题已被证实。

跨批次保留“待答问题、证据 ID、判断及未决事项”的工作记录。不要反复把前一批摘要再压缩而丢掉出处。

## 5. 如何真正整合，而非拼接摘要

先建立同一比较坐标，再把每篇填进去。例如研究“复原 Agent 如何规划工具调用”时：

| 比较维度 | 需要的证据 |
| --- | --- |
| 决策对象 | 工具选择、调用顺序、参数、停止条件分别由谁决定 |
| 状态与反馈 | 使用什么观测，如何判断退化、质量和失败 |
| 规划方式 | 一次规划、逐步决策、搜索或学习策略的具体过程 |
| 记忆 | 存什么、何时更新、怎样检索、是否跨任务复用 |
| 学习成本 | 训练数据、监督／奖励来源和训练时开销 |
| 推理成本 | 工具调用、模型调用、延迟及对应测量条件 |
| 证据与边界 | 消融、失败案例、评估协议和未验证部分 |

可先从地图里的 AgenticIR、MAIR、SEAR、Causal-AgentIR 等候选查起，再通过全库检索补充。这里仅举检索流程，不预先断言它们的机制差异或性能排序。

每个单元格保存结论、证据位置、证据性质和条件。然后才能产生三类整合结果：

1. **共性与分歧：**哪些设计解决相同问题，哪些其实服务不同目标。
2. **可比与不可比：**数据、退化、工具池、训练设置不同的分数分组展示，不能直接排总榜。
3. **研究假设：**可能组合的模块、待验证的缺口以及验证实验。明确这是建议，不能写成已有论文结论。

若两篇看似冲突，优先核对实验条件、术语含义和版本；不为形成一致叙事而抹去冲突。

## 6. 专题笔记如何复用

专题笔记按真实问题创建，例如“工具规划与记忆机制比较”。每份保留：问题、范围、纳入与排除论文、比较表、证据、未决事项、依赖的源版本和更新时间。

再次遇到相近问题时，先检查范围与版本，复用其中仍有效的结构和证据入口，再回读本次答案所依赖的重要原文片段。不能把上次 AI 结论当作新的独立证据。

源论文变化时，仅将依赖它的单元格和结论标记待复核；首次实现可保守地使整份相关专题过期，不必一开始就做复杂的局部增量推理。

## 7. 建议目录：尽量少增加东西

下面均为拟新增内容，不是当前已存在的实现：

```text
图像复原/
├─ 知识地图.md                  分类与关系的唯一维护入口
├─ Agent阅读指南.md             短入口：阅读流程、索引位置、更新规则
├─ AgenticIR-55374df7f41b/
│  ├─ source.pdf / document.md / 原有附件与报告
│  └─ 理解摘要.md               AI 按来源维护，用户也可直接阅读
├─ 其余论文目录/
├─ 专题/
│  └─ 实际完成的专题分析.md     按需生成，不预建空文件
└─ .paperbridge/
   ├─ 原有维护说明与验收记录
   └─ index/
      ├─ catalog.jsonl         全库短索引
      ├─ sections.jsonl        章节、文本块、证据位置
      └─ state.json            版本、来源哈希、覆盖与依赖状态
```

源文档保持英文，理解摘要和专题笔记用中文，术语保留英文别名。无需生成逐句译文。

理解摘要是此次设计引入的 AI 工作资料，不要求用户维护阅读进度。实施时需同步修改现有“当前不创建阅读卡”的维护约定，以及“每次先完整读地图”的入口规则，避免旧规则和新流程冲突。

入口存在不代表 Agent 会自动发现。实施时必须在实际任务入口明确引导读取 `Agent阅读指南.md`；若通过工作台调用，则由工作台传入库路径和入口。每篇已有的 `AGENT_README.md` 仍保留其原有用途。

## 8. 索引和维护分工

**程序负责确定性工作：**扫描论文、计算哈希、提取页码和章节位置、检测链接、输出检索片段、检查版本。

**AI 负责语义工作：**解释机制、形成带证据的理解摘要、识别条件差异、维护合理关系、撰写专题分析。

建议首版提供四个操作能力；以下名称只是接口草案：

```text
catalog(scope)                  返回紧凑论文清单与覆盖状态
search(query, paper_ids, type)   返回命中片段、章节、页码和展开入口
read_section(paper_id, id)       返回章节或指定证据块及上下文
open_evidence(paper_id, id)      定位原页／裁片供视觉核对
```

先用本地关键词检索、英文别名和章节过滤建立可用闭环。普通全文搜索只返回片段与位置，不能将全部命中文件整篇塞进上下文。若验收发现概念改写经常漏检，再评估语义向量检索；是否值得引入由检索质量和维护成本决定。

文件组织、索引提取和关键词检索不需要额外模型 API。理解摘要可以由当前可读本地文件的 Agent 分批生成；这仍然消耗模型上下文和时间。若以后要求无人值守持续生成，才需要确定可程序调用的模型执行方式。

### 8.1 更新规则

- 分别记录 PDF 哈希、实际使用的 MD／修订内容哈希、地图哈希、摘要版本和索引生成规则版本。
- PDF 未变但 MD 修订了，也需要重新检查定位和摘要；存在修订稿时必须先确定有效来源。
- 新论文先进入全库目录，即使理解摘要未完成也必须可检索。
- 原文变化先标记该篇摘要和相关专题过期，再更新；不得继续以已同步状态使用旧结论。
- 地图分类改变，只刷新派生标签；无需无理由重新阅读全部正文。
- AI 更新保留用户手写内容，并记录来源版本；出现冲突时展示差异，不整篇覆盖。
- 阅读覆盖、解析完整性、证据核对是不同状态，不合成一个含糊的“已完成”勾选。

## 9. 实施顺序与验收

### 第一阶段：验证三篇闭环

选两篇可比较的 Agent 论文，加一篇机制不同的统一复原论文，例如 AgenticIR、SEAR、DPMambaIR。建立三篇的章节索引和有依据的理解摘要，同时给全部 25 篇建立短目录，保留全库原文检索兜底。

用实际问题检查“找到论文 → 找到章节 → 核对证据 → 中文比较”是否顺畅。发现摘要缺少必要字段时，先调整格式，再扩展全库。

### 第二阶段：扩展到 25 篇

逐批生成核心章节理解摘要，记录每篇未读范围；建立全库的章节和证据索引。新增资料只处理新增篇，已有资料按版本判断是否需要重读。

首次阅读成本在这一阶段真实发生，不能省略后宣称 Agent 已理解全库。

### 第三阶段：沉淀专题，再决定是否自动化

先完成用户实际需要的两三个专题。若经常重复使用，再把检索入口、增量更新和失效提示接入工作台。向量检索、复杂知识图谱和后台调度都放在有明确需求之后。

### 验收题与记录

至少选 8 道实际问题，并人工检查参考证据：找论文、解释方法、公式含义、实验数值、两篇比较、全库分类、无答案问题、源文档修订后的重查。

分别衡量：

- **检索覆盖：**已知相关论文及必要证据是否被找到；全库问题是否逐篇登记覆盖。
- **回答依据：**重要事实有无可打开且支持该断言的原文；不能只统计链接存在。
- **数值与公式：**关键内容是否与原页相符，协议是否完整。
- **更新正确性：**修改某篇有效来源后，是否能发现旧摘要和专题过期。
- **成本：**记录首次建库成本，以及后续每问读取的篇数、块数、实际输入 tokens 和耗时，分别评估。
- **未知处理：**不存在或未覆盖的信息是否被明确保留，而非补写成事实。

与临时搜索全文、人工选读的现有流程比较，确认答案质量和证据完整性没有因省上下文而下降，再将其设为默认阅读方式。当前尚无检索召回率、节省比例或响应速度的实测结论。

## 10. 建议采用的第一版

采用“短索引 + 单篇理解摘要 + 可定位原文块 + 按需专题”即可。用户继续在 Obsidian 看地图、原文和专题；Agent 在后台遵循检索与证据规则。

首要投入是把核心机制、实验条件、阅读覆盖和证据入口记录准确。原文始终是事实来源；摘要负责减少重复理解，索引负责减少无关阅读，专题负责积累有依据的跨论文分析。
